# Требования к организации внутренних совещаний

Версия от 16 ноября 2026 года. Основание — карточка кейса, материалы инициации и интервью от 13 ноября. Приведённые ниже критерии конкретизируют требования для будущей проверки, но ещё не подтверждают их реализацию в 1С.

Обозначения источников: **К** — карточка кейса, **И** — интервью 13 ноября, **П** — проектное предложение команды.

## Функциональные требования

| ID | Требование | Основание | Критерий проверки |
|---|---|---|---|
| FR-01 | Создать внутреннюю встречу с темой, датой, временем, длительностью и организатором | К, И | Сохранённая карточка содержит обязательные сведения |
| FR-02 | Задать участников и повестку | И | Каждый выбранный сотрудник присутствует в списке ровно один раз |
| FR-03 | Показать занятость выбранных сотрудников | И | Организатор видит доступность на нужный интервал с учётом доступных ему прав |
| FR-04 | Подобрать общее свободное время | И, вариант обсуждался | На тестовом наборе система предлагает подходящий интервал либо сообщает об отсутствии общего времени |
| FR-05 | Выбрать и забронировать переговорную | И | Один ресурс не получает две активные пересекающиеся брони |
| FR-06 | Учитывать корпоративный ресурс Zoom | И | Ресурс ВКС выбирается для интервала, конфликт брони обнаруживается |
| FR-07 | Отправить приглашения участникам | И | Каждому участнику доступно приглашение с актуальными временем, местом и темой |
| FR-08 | Принять или отклонить приглашение | И | Ответ конкретного участника отображается организатору |
| FR-09 | Указать причину отказа | И | Пояснение отказа доступно организатору в контексте встречи |
| FR-10 | Показать сводку ответов | И | Отдельно видны подтвердившие, отказавшиеся и не ответившие |
| FR-11 | Перенести встречу | П на основе исходной модели | Новое время и ресурс проверены, участники уведомлены, ответы на старую версию не считаются актуальными автоматически |
| FR-12 | Отменить встречу и освободить ресурс | П на основе исходной модели | Встреча помечена отменённой, бронь снята, участники получили изменение |

Для FR-04 необходимо уточнить приоритет: обязательная функция первой версии или дополнительное удобство. Для FR-06 речь идёт об учёте брони ресурса, а не о подтверждённой интеграции с API Zoom. Правила повторного ответа после переноса и обязательность комментария при отказе нужно согласовать отдельно.

## Требования к качеству и ограничения

| ID | Условие | Проверяемый результат |
|---|---|---|
| NFR-01 | Разграничить доступ | Пользователь без необходимых полномочий не видит лишние сведения и не меняет чужую встречу |
| NFR-02 | Сохранять согласованность встречи и ресурса | Не возникает подтверждённой встречи с неудавшейся бронью, конфликт явно показан организатору |
| NFR-03 | Показывать актуальные ответы | Ответ относится к определённой версии приглашения |
| NFR-04 | Сначала использовать типовые механизмы | Необходимость доработки обоснована результатом проверки целевой версии |
| NFR-05 | Проверять на тестовых данных | Демонстрация не использует реальные персональные данные и рабочую базу компании |

NFR-01–05 — предложения для согласования и технической проверки. Способ реализации зависит от редакции 1С и настроенных прав.
